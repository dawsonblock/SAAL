# Physical release reproduction

Use the explicit complete-release ZIPs, not GitHub's automatically generated branch source ZIPs. The latter may substitute Git LFS pointers for real objects. For a Git checkout, install a native Git LFS binary and run `git lfs pull` before verification. This repair preserves physical historical artifacts and records each changed parent file.

The main release's `reproducibility-evidence/physical-inventory.json` binds every included physical file other than its three control files (inventory, signed statement, public key). `signed-release.json` binds the inventory, parent identity and exact change accounting. Root MANIFEST.sha256 excludes itself and those control files plus changes.json to avoid circular hashes; the signed inventory covers the manifest and changes. Older manifests/signatures retain their historical meanings; their old source verifiers will reject this changed source. Authenticate the new controller pin separately. Bundled-key verification proves internal consistency, not independently trusted identity or empirical truth.

Use the exact pinned platform profile under configs/dependency-locks. The recorded local environment is macOS ARM64/Python3.12; fresh Linux checks use x86_64/Python3.13. The full Linux profile is downloaded with `--require-hashes --only-binary=:all:` and installed offline from verified wheels using `--require-hashes`. With a virtual environment created without pip, invoke management/inventory using the host pip's `--python ENV/bin/python` option. The test helper path above is required for importlib mode. Outside these tested profiles, compatibility is unverified.

On the additive results branch, use `--allow-results` to verify the unchanged main subset. That explicitly excludes results/, which must be checked using its own publication manifest and signed delivery record. It does not authorize results as qualification. An edited main file still fails.

Historical baseline/candidate weights listed in manifests are included. External pretrained snapshots remain separate dependencies pinned by their existing upstream revisions and file digests.
