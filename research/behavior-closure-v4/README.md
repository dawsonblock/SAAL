# SAAL-RSI Behavior Closure v4

Public corrective learning and versioned qualification engineering. This study
does not begin with a qualified model, human-reviewed labels or independent
custody. External deployment remains prohibited.

The previous v3 campaign has been completed through an explicitly signed
additional training budget, retaining its learning settings. Original failures
and consumed reservations are preserved. V4 is a
separate, failure-informed public experiment with fresh identities and budgets.

## Changes

- A strict behavior screen rejects malformed/nonfinite metrics without changing
  the 90% complete-pair, 80% worst-family, four-class and zero-critical gates.
- Error audits retain actual wrong proposals and both members of failed pairs.
- 1,152 newly authored cases (576 pairs) add short and composed supervision.
  The old 5,464 records remain unchanged. Training has 4,608 cases, development
  960 and exposed regression 1,048. All training classes have 1,152 cases.
- The blind review packet covers the new cases. No human review is fabricated.
- A separate v6 family-evaluation path integrates exact physical checkpoints,
  evaluator-signed public reconstruction, custody review, protected-source
  screening, witness attempts, fresh-process CPU inference and recomputed
  statistical/retention gates. See ../../docs/PRETRAINED_QUALIFICATION_V6.md.

## Registered comparison

Five seeds compare trained heads on frozen ModernBERT against fixed-rank LoRA
plus the same trainable head. All receive the same data and 16,000 sample
exposures through 1,000 updates with batch 8 and accumulation 2. Initial,
development-selected and terminal checkpoints remain distinct. One full-tuning
seed adds a declared head warmup and smaller encoder learning rate; it is an
exploratory baseline, not a five-seed full-tuning comparison.

Compared with v3, both the corpus and sample exposure change. V4 is not a clean
estimate of either change alone. The original and newly added diagnostic
populations are reported separately. Public regression never selects weights.
No dynamic-rank or recursive-improvement claim is made.

Every job has a signed T4 budget and platform hash lock. The two stages have
independent durable ledgers, monitored deadlines and exact-session cleanup.
The full-tuning stage additionally requires sufficient local artifact-recovery
capacity. A storage/GPU/interruption failure is retained, not silently retried
under another configuration. Time accounting is not a financial billing cap.

## Commands

Use the pinned Python environment and the controller's existing private key
outside the repository. Preparation is one-use and precedes execution:

```sh
python campaign.py prepare /private/path/to/controller.key
python campaign_amended.py run paired
python campaign_amended.py run full
```

Run core tests with PYTHONPATH=src from the repository root; corpus tests also
need reviewed-decision-corpus/src. The report records actual test outcomes and
training results after execution. A preregistration or passing software test is
not a passing behavior result.

The original signed protocol is preserved. Its separate signed source amendment
records the qualification verifier's host-portability correction before any v4
training starts. The learning worker, datasets, seeds, optimizer settings,
budgets and job digests are unchanged. Use the amended driver after confirming
the matching fresh QA evidence; the original driver deliberately rejects drift.

The initial paired v4 controller suffered a broken output pipe after recovering
three runs. Its fourth run remains interrupted and six original reservations
remain unstarted. A signed `continuation-01` admits one additional bounded
training budget for those seven roles. The original ledger and outcomes are
unchanged. `continue_registered.py` rejects completed-run retry and altered
job/source identities. The continuation controller writes to a persistent file
and runs in its own process session; monitoring and the named-session watchdog
continue independently of the interactive tool connection. This is research
process management, not hostile-code containment.

Use `python research/behavior-closure-v4/monitor.py` from the repository root
for current progress. It derives per-run counters from the preserved events
using the already tested v3 parser, marks the reconciled interruption, and
does not carry a previous model's final step into a new model's preparation.
It is an observer, not an evaluation or deployment authority.

`public_baselines.py` evaluates the unchanged historical first-keyword rule and
a majority control chosen exclusively from training labels on the exact public
population. Public research selection, final training and qualification remain
separate. Initial, best and terminal snapshots all remain visible.

`colab_tests_v4.py` runs core, corpus, historical reporting and project suites in
a fresh hash-locked Colab CPU runtime. Actual XML counts and exact input hashes
appear with each attempt; a successful earlier source snapshot is never silently
claimed to cover later tests.

The physical delivery ZIP includes all recovered generated checkpoints. Repeated
full-model tensors are stored once by content hash and restored by
`materialize_tensors.py`. Authenticate the ZIP SHA-256 against the separately
delivered value before executing extracted code. A trusted copy of
`verify_capsule.py` then verifies the controller signature and every logical
file; the controller public key must come from a trusted source. An included
key is useful for consistency checking, not independent trust establishment.
`extract_capsule.py --reuse-root ...` can read every ZIP member completely while
hardlinking identical, hash-verified tensors into a new directory to conserve
disk. Linked bytes are shared; keep them immutable during verification/replay.
The pinned upstream pretrained cache remains an explicitly separate prerequisite.

## Unmet external requirements

Two human reviewers and adjudication, genuinely independently sourced final
families, independently managed evaluator/custodian/witness services, verified
deployment controls, and a passing frozen candidate are prerequisites for an
independent qualification. Local signed assertions cannot supply those roles.
Sequential adaptation is conditional on a competent candidate and a separately
frozen matched protocol; no automatic authority transition follows training.
