# v0.9.1: measured development repair and monitored Colab execution

## What changed

The old adapter optimized random small batches and exported its last update. Lower minibatch loss was misleading: the demo stayed at 83.3% accuracy and changed which safety category failed. v0.9.1 uses explicitly signed adapter training data, class-balanced full-batch cross-entropy, and retains the best checkpoint by worst-category accuracy, then category-macro accuracy, then overall accuracy. Step zero is eligible, so training that fails to improve development performance retains the incumbent. Exported losses now measure full-training unweighted cross-entropy at the exported checkpoints; these are not interchangeable with v0.9.0 final-minibatch losses.

The public demo also encoded nuisance annotations differently between training and development. Explicit demo augmentation varies that annotation and retains the original training cluster identity. This is a demonstration-specific transformation, not automatic label inference or independent extra evidence. Adapter data are checked against development and final holdout partitions. Jobs use a closed v2 schema; historical v1 evidence stays in docs/history.

CPU and GPU baseline training can differ because their random minibatches differ. A job can now pin an existing baseline's exact SHA-256 and train only its adapters. The controller bounds and verifies the file, the worker validates finite tensors and architecture, and the recovered baseline must retain the pinned bytes. This allows a matched comparison to the actual earlier GPU incumbent rather than replacing it with a stronger CPU baseline.

## Monitoring and cleanup

The official Colab CLI installer previously timed out after quiet dependency installation. The new installer emits heartbeats every five seconds and has a 300-second dependency deadline. Remote workers emit update counts, elapsed time, losses, development scores and GPU memory. The controller streams logs, limits output, records phases and local heartbeats, and enforces an overall deadline. A separate process watchdog targets only the newly generated exact session name if the controller disappears. Success requires runtime stop followed by an explicit not-found status, checkpoint hash/schema checks, GPU identity, and CPU reload prediction agreement. Other sessions are preserved. Monitoring is observational; worker claims are not remotely attested.

## Reproduce a frozen-baseline development experiment

Install the model dependencies in a separate environment. Generate demo-data, including adapter-train.json, using `python -m saal_rsi.model_cli demo-data --directory DIRECTORY`. Use `job-create --help` for complete required signing and data arguments. Add `--adapter-train adapter-train.json --baseline baseline.safetensors --baseline-steps 0 --adapter-steps 500 --adapter-learning-rate 0.01` when creating the signed job. Supply the same baseline with `run --baseline baseline.safetensors --backend colab`. The baseline shipped with examples/model_demo/checkpoint is the earlier actual T4 incumbent. Use a newly generated controller key for a new job; packaged keys are public verification keys only. Provisioning consumes the user's Colab quota.

## Scope and remaining limitations

All tuning uses the same 48 public development records. Results on those records are selection evidence only. No new final holdout was used for this repair; the v0.9.0 failed qualification is retained as historical evidence. Qualification and external deployment remain unavailable for these new weights until the separate existing admission workflow runs with a fresh independently anchored holdout. Do not reset a consumed ledger or relabel development results as holdout results.

This is an 8,422-parameter synthetic byte classifier with low-rank adapters, not a pretrained language model or QLoRA implementation. Attention pooling is insensitive to byte order. FAST is absent from the demo training labels and is explicitly reported as missing; 100% on this demo cannot establish capability on FAST requests, new language, or real user welfare. Repeated templates and augmentation are correlated, so nominal record counts do not establish statistically independent sampling. Signatures protect integrity, not the truth of worker measurements. Same-UID isolation, local key/ledger custody, dependency version pins, watchdog cleanup, billing controls, external timestamps, and cloud authenticity remain incomplete hardening. Colab is a compute backend, not the evaluation authority or a security boundary.
