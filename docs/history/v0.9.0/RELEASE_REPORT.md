# SAAL-RSI v0.9.0 release validation

This release adds real neural optimization and checkpoint comparison on synthetic assistance decisions. It does not establish AI alignment, pretrained language-model improvement, independent evaluator custody, GPU performance, or production security.

- Full suite: **201 tests passed in 31.10 seconds** on Python 3.12.0, macOS 26.2 arm64. Includes all 175 v0.8.1 cases and 26 new cases. The new tests actually optimize a supervised baseline and low-rank adapter, inspect nonzero learned weights, reload checkpoints, and evaluate signed holdouts. No new test was skipped on this validation host.
- Negative coverage: partition/cluster leakage, job/key tampering, checkpoint hash corruption and tensor-shape poisoning, worker self-approval, unsafe archive paths, holdout reuse, interrupted consumed evaluations, re-signed metric manipulation, submission replay/budget exhaustion, abandoned alpha allocation, and learned forbidden proposals denied by the existing child executor.
- Official Colab CLI 0.6.0 is already installed; version and new/exec/download help were inspected. The backend's success/result-recovery and failure/cleanup command contracts were tested with controlled subprocess responses. A signed job and offline submission plan were generated. **No authenticated Colab runtime was provisioned, no remote GPU training ran, and account billing/compute balance was not tested.**
- Complete local CLI workflow ran: separate controller/custodian/evaluator keys, public data, signed job, submission budget, real training, private plan, custodian anchor, consumed evaluation, signed report, and pinned-key full verification. Editable installation and installed CLI startup were checked in a separate neighboring environment.
- Local model demo: 60 public synthetic final cases, 60 nominal clusters, ten cases per category. Baseline accuracy 0.8333333333333334, candidate accuracy 0.8333333333333334, ten winning and ten losing clusters, one-sided sign-test p=0.5880985260009766. The candidate failed positive-gain and zero-safety-error gates because all ten clarification cases were wrong. **Research qualification failed and external activation remained prohibited.** No rerun or holdout tuning was used to manufacture a success.
- Actual training losses: baseline final loss 0.5289172530174255, adapter final loss 0.4635871648788452. Lower training loss did not imply qualification. Public demo checkpoints, signed job/receipt/report, public verification keys, and summary are under examples/model_demo. Private keys, final private plan, mutable databases, and private execution logs are excluded.
- Regenerated legacy rule-policy example signatures/source/runtime verify and qualification still fails; historical v0.8.1 examples are archived separately. New neural weights are not admitted by the legacy frozen-rule promotion API.
- Dependency identity: torch 2.10.0, safetensors 0.8.0, cryptography 48.0.1; pytest 8.4.2. requirements-model.txt supplies the worker/local learning versions. These are version pins, not dependency hash locking or supply-chain attestation.
- Clean-extraction validation runs the full suite and complete manifest checks before and after tests. The exact final ZIP checksum, file count, captured test result, and example verification are recorded in the companion SAAL-RSI-v0.9.0-ZIP_VALIDATION.json. A base-only installation can skip optional model cases and must not claim this release's complete validation.

Not implemented or tested: pretrained Hugging Face model admission, tokenizer/template provenance for LLM generation, QLoRA, Colab Enterprise managed jobs, immutable/WORM storage, a remote independently operated custodian/evaluator, remote attestation, distinct-UID/container isolation, cloud byte/billing caps, cross-device learning reproduction, Linux/Windows or other Python-version runs, real-world side effects, or external deployment. See docs/V0.9.0_ARCHITECTURE.md for the concrete follow-on plan.

The exact cluster sign test depends on independent sampling and a justified null. Public repeated-template data does not establish that assumption; this demonstration has no population-confidence interpretation. Local signatures and consistency checks still trust truthful evaluator measurements and protected ledger/key custody. Same-UID operators can reset or replace stores. Colab cleanup is attempted, not a guarantee of stopped billing after failures.
