# SAAL-RSI v0.7.0 release report

**Scope:** simulated, controlled research integration of two user-supplied source archives.

## Sources included

- SAAL v0.5.0 original source files, tests, docs, security notes and public reports.
- Dream-RSI Governed v1.0.0 original source files, tests, docs, and the user-supplied upstream reference materials (subject to source rights).
- New `saal_rsi` bounded integration, commands, tests, protocol and security documentation.

## Verified at build time

- Inherited SAAL suite: 86 passing tests.
- Inherited Dream-RSI suite: 16 passing tests.
- New integration suite: 16 passing tests.
- **Total: 118 passing tests** (from the consolidated checkout, Python 3.11+).
- End-to-end CLI: `discover` generated a development-only parameter proposal; `plan-create` generated evaluator-held seeds; `keygen` generated an Ed25519 key outside the release tree; `qualify` produced a **failed** qualification on previously unprovided synthetic seeds; `verify` validated the signed negative result with a pinned public key.
- The evaluated candidate's one-sided bootstrap lower bound was negative. Correct behavior: **not qualified; no promotion authority**.
- SAAL's inherited synthetic demonstration was executed in the merged checkout.
- Dream replay RNG corrected for per-action common random numbers so policy IDs no longer choose the outcome random stream.

## Release exclusions

- No private or signing keys, evaluator private holdout plan, real credentials, or runtime-issued capability tickets.
- No live tool connector that can book appointments, transmit messages, spend money, deploy a model, or change safety policy.
- No claim of independent host/UID isolation, production safety, frontier-model corrigibility, or general alignment guarantees.
- No replication of the paper's published algorithm/Kernels benchmarks claimed.

## Scientific caveats

The discovered policy was not qualified on the private synthetic experiment and must not be activated. Public demonstration material under `examples/` is for testing only. Even a positive signed test report would not amount to a guarantee for unseen tasks or authorize model activation. `qualify` and `verify` attest to research results; no independent human promotion component is linked to these reports.
