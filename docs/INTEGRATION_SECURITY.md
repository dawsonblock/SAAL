# v0.8 security scope

The trusted computing base includes the evaluator, process bridge, executor code, source/config identity measurement, custodian service/ledger, signature verifier, human approval service, and their deployment environment. All current effects are nonbinding in-memory synthetic events.

The proposer selects only frozen rule candidates. Actor workers start in fresh isolated-mode Python interpreters, with scrubbed environment and separate temporary working directories; JSON pipes send only public scenario views. They inherit neither evaluator keys nor its address space. The executor creates its own authority secrets and scope. It checks capabilities against exact action, policy, nonce, delegation budget, and allowed slot set before emitting a simulated event. Actual malicious actor attempts are logged as behavioral failures even when denied.

This is **process separation, not an adversarial OS sandbox**. Workers use the same UID, can read accessible host files and source, and are not network or process-inspection confined. Public synthetic IDs encode seeds, and simulator code is shipped: a hostile arbitrary actor could regenerate hidden goals. Arbitrary actors remain inadmissible; the schema and fixed implementation are material controls. Real secrecy requires separate identities/hosts, undisclosed evaluator generation, filesystem/network confinement, authenticated services, and platform-specific qualification. No distinct-UID or hostile-code sandbox qualification was run.

The custodian uses a distinct key and signs a receipt binding plan, proposal, identity, and configuration before any evaluation. The ledger atomically reserves seed IDs and allocates alpha at anchoring. Consumption precedes evaluation and persists across restarts; interrupted runs cannot reuse an anchor. Seeds cannot be reanchored even for another candidate. The fixed protocol family cannot be reset through the API. Concurrency uses SQLite transactions.

Independent anchoring relies on **independent custody and publication**, not the local wall clock or SQLite file. The local example is not an external timestamp authority. A same-UID operator can delete or restore the ledger, read the sealed plan, replace source, or falsify host measurements. Separate keys are necessary but do not prove separate operators. Ledger consumption in the CLI is local; an authenticated remote custodian service and a distinct-UID end-to-end deployment are not implemented. No remote timestamp receipt, HSM, transparency-log inclusion proof, encrypted key custody, OS attestation, or backup rollback prevention is implemented. Do not describe the local demo as independently hosted evaluation.

Identity records runtime source, tests, configuration/tools, project metadata, Python executable hash and version, platform, and versions of cryptography/CFFI/pycparser. Active plan configuration is also receipt-bound. Checks before and after qualification detect normal drift. Measurements are not hardware attestations and do not enumerate every dynamically loaded OS library. The manifest provides complete release-file inventory; execution identity deliberately excludes generated reports/docs to avoid circular evidence hashes.

External activation is centrally prohibited. The old Dream activation entry point and `--promote` cannot bypass that prohibition. Legacy archival signing remains available as `issue_archival` and its manifests never authorize integrated activation. Optional inherited LoRA/offline admission experiments remain a separate synthetic research feature; their artifacts cannot enter the closed SAAL-RSI Candidate schema. The research-only activation API requires exact independent human approval and consumes it once. Trusted replay stores must be protected against deletion/rollback by deployment controls. Direct calls to Python policy classes by a same-UID programmer are not prevented.

IPC bounds and timeouts limit malformed responses from fixed workers; they are not comprehensive CPU/memory resource containment. Executor nonce state is per run because all events are in memory; cross-service durable external effect recovery is unimplemented. No real calendar, network tool, purchase, or system operation runs. Maintain these restrictions until independently qualified external adapters exist.
